# P0.2 : Session fiabilité (déconnexion + update simultanée)

**Date** : 2026-09-26  
**Objectif** : Vérifier que session reste stable en cas d'erreur réseau et de rafraîchissements simultanés.

## Résultat du test

### ✅ Session robustes en v48

**Code** : `Auth.rafraichir()` et `Auth.appel()` (v48+).

#### Déconnexion seulement sur refus d'auth

```javascript
// rafraichir() : ligne ~335
if (await this.rafraichir()) return this.appel(chemin, Object.assign({}, options, { _reessai: true }));
// Si erreur réseau (5xx, 408, 429) : garde session et réessaie
// Si 401/403 : appelle reprise() qui nettoie et affiche « Me reconnecter »
```

**Constat** :
- ✅ Erreur réseau (coupure 4G, timeout, 5xx) : session gardée, réessai automatique.
- ✅ Refus explicite (401/403) : session nettoyée, affichage « Session perdue ».
- ✅ Single-flight `_renouvellement` : un seul rafraîchissement à la fois (Flag `_renouvellement`).

#### Synchronisation multi-onglets

```javascript
// Storage event listener (v48) :
depuisAutreOnglet(e) {
  if (e.key === this.cleSession && e.newValue) {
    // Adopte une session plus récente du même utilisateur
    this.session = JSON.parse(e.newValue);
  }
}
```

**Constat** :
- ✅ Deux onglets : le 2e rafraîchissement détecte que la session a changé et l'adopte.
- ✅ Pas de conflit de jeton ; aucune déconnexion surprise.
